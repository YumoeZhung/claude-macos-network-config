# 直连规则收紧与回滚

记录日期：**2026-11-17（日本时间）**。这是 Mac 本地 DNS 跟随配置的一次变更与验收记录；没有同步修改手机、原生远程订阅或其他订阅。实际规则、完整配置和备份只保存在本机，不随本文公开。

## 目标与范围

采用 **本地网络 + 用户明确需要的业务例外 + 国内 IP / 国内媒体规则直连，其余默认代理**。业务例外由用户选择，所以不称为“只有国内目标直连”。Typeless、向日葵只是本机案例。

保留原有代理分组和匹配顺序，撤销不需要的特殊直连待遇。这次没有重写整份订阅，没有增加整个 Chrome 强制代理规则，也没有新建浏览器隔离环境。

| 项目 | 变更前 | 变更后 |
|---|---:|---:|
| 全部规则 | 2,479 | 2,374 |
| 显式指向 `DIRECT` 或直连组的规则 | 152 | 47 |
| 本次撤销的显式直连例外 | — | 105 |

**47 不是全部可能直连的路径数量。** 原有 Bilibili、China-Media 等分组规则及其直连选择仍保留；审查必须沿代理组追踪到末级，不能只搜索字符串 `DIRECT`。

删除范围包括 Google / Microsoft / JetBrains 下载或更新、广告统计、PayPal、部分游戏、DDNS、BT/PT、下载器进程和宽泛下载关键词等未经用户指定保留的例外。保留指定业务的六条规则、本地网络和路由器管理入口、原有国内 IP 网段及两条 GeoIP 规则。

这些数量是本机快照，不是其他人的删除指标。不要照抄规则编号、按“前六条”判断业务用途，或机械删除同样数量的规则；应按实际内容、规则目标和用户需求确定清单。

## 两条 GeoIP 规则与默认兜底

```yaml
- GEOIP,CN,🎯 直连,no-resolve
- GEOIP,CN,🎯 直连
# 中间仍可能有其他规则，此处只展示相关条目。
- MATCH,🐟 Others
```

- 带 `no-resolve`：已有可用于匹配的真实目标 IP 时检查归属，不仅为这条规则主动发起域名解析。
- 不带 `no-resolve`：需要时解析域名，再按国内 IP 数据库判断。
- `MATCH`：处理前面没有匹配到的请求。本次实际链为 `Others → 代理 → 当前手动日本节点`。

规则按顺序匹配，先命中的决定路径。GeoIP 根据目标 IP 判断，不要求域名以 `.cn` 结尾，也不等于经过人工确认的可信网站清单。

**删除域名直连例外不等于强制该域名走代理，更不等于屏蔽服务。** 后续解析到国内 IP 时仍可能命中 GeoIP 直连；海外目标在没有其他匹配时落到默认代理。本次 Google 下载和 PayPal 实测均落到默认代理。

## 为什么仍有 2,374 条规则

这是海豚湾原订阅继承下来的整套分流规则，不是给 Claude 单独编写了两千多条规则。主要包含网站域名、影音与服务分类、进程规则、本地网段、国内 IP 判断和最终兜底。

多个服务组目前最终指向同一个日本节点，但保留了服务分类。此次只收紧直连例外，没有顺带压缩全部规则。规则数量不能替代对实际匹配路径的验收。

## Agent 执行顺序

1. 确认 Desktop、Code 和相关任务停止；扩展关闭需单独确认。不要为了检查启动 Claude。
2. 发现当前本地订阅、全局和订阅覆写、生成配置、控制器及全部组选择。先列出精确删除清单与保留清单。
3. 在仓库外建立私有备份：源配置、生成配置、相关覆写、GUI 元数据、规则前后清单、全部组选择及 SHA256。不要把节点凭据、真实出口或本机路径提交到公共仓库。
4. 生成候选，只修改已授权的规则部分；结构化核对非规则字段不变。不得更改 DNS、节点参数或其他订阅来掩盖规则问题。
5. 使用与运行内核版本一致的 Mihomo 校验源配置与生成候选。本次为 v1.19.32。服务目录的二进制不可执行时，可核对应用包内同版本二进制用于校验，不调整服务目录权限。
6. 确认源文件没有并发修改后，原子替换本地订阅，再通过 Clash Verge“重新激活订阅”加载；不要点远程订阅更新或改节点。
7. 比较源文件、生成文件、运行规则与界面；逐条核对保留规则的类型、匹配值、目标及顺序，确认所有组选点不变。
8. 使用无 Cookie、无令牌的独立请求验收目标路径；分别记录代理、业务直连和失败项。维护不要求重新登录、付款或清理 Cookie。

回滚也先结束相关任务。当前源文件哈希仍等于本次变更后的哈希时，可以恢复备份源文件并重新激活；若已有后续修改，合并恢复被删除规则，不直接覆盖整份文件。恢复后重新核对规则、节点和连通性。

## Cloudflare 与故障边界

同日修改前的独立检查中，`www.cloudflare-cn.com` 命中国内 GeoIP 直连，而 Claude 和已检查的验证域名走日本节点。此次没有为 Cloudflare 中国增加强制代理规则；国内 GeoIP 策略保留。Net.Coffee 的国内探针不是经证实的 Claude 遥测清单，共用 Cloudflare 基础设施也不能据此认定存在账号关联探测。

用户本轮选定的故障范围是：**TUN 与内核持续运行，只有节点 timeout / error 时，原本应走代理的请求失败，不回落直连；必要直连业务仍可联网。** 当前相关链是手动选择组，没有发现节点失败后自动选择 DIRECT 的配置。手动组里存在直连选项不等于自动故障回退，但仍应避免误选。

本轮没有进行节点故障注入、停止内核或断网测试，因此不把一次超时写成“断流即断网已验收”。TUN 开关开启也不证明内核始终存活；内核退出、TUN 消失时的系统级阻断仍未验证。仅启用 `strict-route` 不能代替该验证。

手机配置没有随此次 Mac 修改自动更新。今后更新订阅时，还要重新应用这份精确删除清单并复查新加入的直连规则，不能只合并 DNS 后就认为收紧策略仍然保留。
