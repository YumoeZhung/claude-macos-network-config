## 踩坑与修正

1. **只关 Append System DNS 不够。** 初始手机仍看到联通解析器，必须核对实际配置、DNS 路由和测试结果。
2. **DNS 写死节点会失去跟随能力。** 早期绑定固定日本 Game，后续改为绑定选择组，以适应必要的节点切换。
3. **引导解析需要独立。** 修改 DNS 的配置曾导致无法联网，修正节点引导解析后恢复；不要让“解析代理节点域名”先依赖该代理。
4. **不能凭编辑器显示判断 YAML 有效。** 手机 WPS 曾显示乱码；应保持 UTF-8，并用内核验证实际配置，避免随手重新保存损坏文件。
5. **重装 Desktop 不一定清除 Gateway。** CC Switch 卸载后，`~/Library/Application Support/Claude-3p` 仍保存第三方部署设置，指向已经停止的本地代理。清理旧 Desktop 第三方资料后恢复官方登录。不要无差别删除 `~/.claude`、项目目录或用户自己的 Codex 路由。
6. **看到 API 域名不代表走 API 计费。** Code 的订阅认证与 API Key 都可能访问相关 API 主机，要看实际认证方式，不能只看域名猜账单。
7. **生成配置不等于运行态。** 实际服务使用的 controller socket 与生成文件记录不同；从运行进程发现正确 socket 后才读取到内核状态。
8. **IPv6 没公网地址与已关闭不同。** 先确认当前不可达，随后完成 Clash 和现有系统网络服务的明确关闭，再次验证 IPv4 正常。
