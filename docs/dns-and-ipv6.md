# DNS、CDN 与 IPv6：检查什么，如何验收

## DNS 一致性不能只看国旗

需要分清三种地址：

| 地址 / 位置 | 含义 | 证据来源 |
|---|---|---|
| 请求出口 | 目标站看到的客户端来源 | 目标 `/cdn-cgi/trace` 的 `ip`、`loc` |
| 递归 DNS 服务器 | 代表你向测试域名权威 DNS 查询的解析器 | BrowserLeaks / DNSLeakTest |
| 目标地址与 CDN 入口 | DNS 返回的目标，以及实际接入的边缘机房 | A / AAAA 答案、服务端 `colo` / `CF-Ray` |

“日本出口、美国 DNS 标签”不能直接说明请求进入美国 CDN。公共 DNS 的分布式部署、Anycast、地址归属数据库差异、代理节点的二次解析都可能影响显示结果。

工程上按以下顺序查：

1. 测试里出现本地运营商解析器时，先查系统 DNS、浏览器 DoH、VPN 接管和 nameserver/fallback。
2. 核对目标域名是否进入预期 DNS 策略，而不只是测试网站自身的域名。
3. 核对 DNS 上游连接的代理链，以及真实解析答案。
4. 请求目标的公开诊断地址，确认本次出口与 CDN 入口。

本次电脑检查，三域名真实 A 答案均为 `160.79.104.10`，内核查询与经当前代理的 Cloudflare DoH 一致；目标诊断均为 JP / NRT。**这个地址只是历史结果，禁止写入 hosts、规则或生产配置固定使用。**

## 当前链路

```text
Claude / Code 查询域名
  → 本机 Clash DNS 返回 fake-ip 映射
  → 应用连接 198.18.x.x
  → TUN / Mihomo 恢复目标域名，按规则选择代理
  → 当前手动节点 → Claude 边缘入口

需要真实解析时：
  Mihomo → Cloudflare DoH → 当前选择组 / 当前节点

建立节点连接前：
  节点域名 → 独立 bootstrap DNS

用户指定的直连业务：
  精确规则 → DIRECT + 对应直连 DNS
```

代理协议可能把域名交给远端解析。内核的 `/dns/query` 能验证其自身真实解析结果，但不能单凭它证明远端节点采用了完全相同的答案。因此还要核对目标端入口，不把配置推断写成远端抓包证据。

## 为什么保留 fake-ip

我们实际走通的方案使用 fake-ip，并取得了目标端出口 / CDN 一致的证据。它用于本地映射和恢复域名，通常不作为公网源地址发送给服务端。

帖子提出禁用 fake-ip、担心 DNS 时序及反向查询。本仓库的选择是保留现有工作模式、用实际路径验证；不把未验证的 redir-host 配置包装成成功经验。若确有兼容性或路径异常，在独立配置里单独测试 DNS 模式，先退出客户端，再重复全部验收。

## 引导解析不等于目标解析

- `proxy-server-nameserver`：解析代理节点的服务器域名。
- `default-nameserver`：为 DNS 上游的域名提供引导解析等，依版本实现确认。
- `nameserver`：常规目标域名的上游。
- `direct-nameserver`：明确直连目标的解析。
- `nameserver-policy`：特定域名的例外，注意优先级及直连解析的 follow-policy 配置。

不能因为配置含国内引导 DNS 就判断 Claude 域名一定在国内解析，也不能因为常规 nameserver 是境外地址就忽略例外规则。查最终配置、运行态和实际请求三层证据。

## IPv6 双层收敛

| 层面 | 目标 | 证据 |
|---|---|---|
| Clash 内核 | 关闭内核 IPv6 流量支持 | `/configs` 中 `ipv6: false` |
| Clash DNS | 不提供 AAAA 答案 | `dns.ipv6: false`，实际 DNS 查询空答案 |
| macOS 网络服务 | 现有上网服务禁用 IPv6 | 每个适用服务 `IPv6: Off` |
| 实际连接 | 没有可用公网 IPv6 路径，IPv4 正常 | 指定两个公网 IPv6 地址连接失败，IPv4 对照成功 |

仅关 AAAA 解析覆盖不了应用直接使用 IPv6 地址的情形。仅依赖公司网络没有分配公网 IPv6，也覆盖不了将来的家庭 Wi-Fi、热点和新网卡。

`::1` 是回环，`fe80::/10` 是链路本地地址；看到它们不需要关闭 AirDrop、删除 utun 或清空系统路由。新网络服务和 VPN 改变时再验收。

## WebRTC 单列

网页 WebRTC 测试可检查该浏览器是否暴露额外公网地址；不能替代 Electron 桌面端或移动 App 测试。被动采样没有 UDP，只能记为“本次未观察到”。要验收语音 / 媒体场景，应由用户正常触发，再观察实际路径；不要后台自动启用麦克风。

## 固定节点的含义

DNS 绑定选择组，便于用户必要时切换地区而保持路径协调。手动节点名称不保证供应商永久使用同一出口 IP。以目标端观察为准，不按节点名称、机场营销标签或“纯净度分数”直接验收。
