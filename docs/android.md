# Android / 小米：手机单独验收

现场手机为小米 17、Clash Meta、联通移动数据，也使用 Wi-Fi。手机采用 DNS 跟随选择组的本地配置；它与 Mac 的具体直连策略、客户端覆写并不自动同步。

手机曾检测到本地联通 DNS，调整后用户反馈：日本节点的 BrowserLeaks DNS 只显示日本，DNSLeakTest 显示日本与美国公共解析器；切美国节点后测试也跟随变化。这是用户提供的浏览器测试结果，未对手机完成与电脑相同的三域名 CDN 诊断。

## 设置顺序

1. 在系统应用信息中强行停止 Claude，确认没有正在进行的任务。
2. 保存当前配置和界面设置，保留原订阅；保持当前节点。
3. 配置下表中的 IPv6 / DNS 项；重连 VPN 使其生效。
4. 启用系统的 VPN 断线阻断，并为 Clash 保活。
5. 分别在实际使用的 Wi-Fi / 移动网络验收；不要开着 Claude 测试切换。

## Clash Meta

| 位置 / 设置 | 目标值 |
|---|---|
| 网络：自动路由系统流量 | 开 |
| 网络：DNS 劫持 | 开 |
| 网络：允许应用绕过 | 关 |
| 网络：访问控制模式 | 允许所有应用；检查没有排除 Claude |
| 网络：允许 IPv6 | 关（按核对过的上游实现，并做版本实测） |
| 覆写 / 常规：IPv6 | 已禁用 |
| 覆写 / DNS：IPv6 | 已禁用，而不是“不修改” |
| 覆写 / DNS：追加系统 DNS | 已禁用 |
| 系统：私人 DNS | 本方案采用关闭，由 Clash 统一解析 |
| Chrome：使用安全 DNS | 本方案采用关闭，由 Clash 统一解析 |

三处 IPv6 控制不是同一个开关。核查过的 Clash Meta 上游 `TunService.kt` 在“允许 IPv6”关闭时不向 VPN 添加 IPv6 地址、路由和 DNS，也未调用 allowFamily 放行该地址族；Android 默认阻断未加入 VPN 的地址族。安装的是其他分支或版本时，应重新核对并实测，不能把开关文字当成唯一依据。

“绕过私有网络”针对局域网，不是允许所有公网流量绕过。需要打印机、NAS、投屏时保留并验收；不需要时可关闭以减少例外。VPN 已接管的流量仍可被 Clash 规则设为 DIRECT。

保持已有 Stack Mode、系统代理及嗅探选项；不要一次把所有“不修改”改成开或关。配置合并后的含义比开关数量重要。

## 小米系统设置

- 设置中搜索 **VPN**，进入 Clash Meta 详情。如果系统和应用支持，开启“始终开启 VPN”与“阻止未通过 VPN 的连接”。仅开前者不能代替后者。
- Clash Meta：允许后台自启动、电量策略选无限制；可配合最近任务锁定。不要对代理应用使用“严格控制后台运行”。
- Claude：可限制后台运行、拒绝位置权限。厂商的后台限制不等于强行停止；变更网络前采用明确的退出 / 强行停止。
- 不需要的精确位置、附近设备权限可拒绝；不为此关闭 Google Play 服务、系统推送或任意修改设备标识。

“阻止未通过 VPN 的连接”会在 VPN 停止时让普通应用断网，这是预期行为；它不阻止 VPN 应用根据自己的规则进行 DIRECT 出站。启用前确认用户接受该影响。

Android 没有可通用于所有机型的“整个系统 IPv6 关闭”按钮。APN 的 IPv4 设置仅影响移动数据，而且可能影响联网；不是本指南的首选步骤。不 Root、不修改内核、不盲改 APN。

## 手机验收

- IPv4 正常，出口符合预期；[test-ipv6.com](https://test-ipv6.com/) 等显示公网 IPv6 不可用。
- [BrowserLeaks DNS](https://browserleaks.com/dns) 与 [DNSLeakTest](https://www.dnsleaktest.com/) 检查没有未经解释的本地运营商解析器。
- 目标域名 / CDN 验收按 macOS 手册中的同一证据标准，不能用手机 DNS 国旗代替。
- 检查休眠 / 息屏后 Clash 仍工作。若测试断线阻断，先停止 Claude，再停止 VPN，以无账号普通网页确认断网，最后恢复 VPN 并重新验收。
- 手机 DNS 测试通过，不代表所有其他 App 都使用相同解析方式；Claude 登录后还需看实际连接。
