# Android / 小米：手机单独验收

现场手机为小米 17、Clash Meta、联通移动数据，也使用 Wi-Fi。手机采用 DNS 跟随选择组的本地配置；它与 Mac 的具体直连策略、客户端覆写并不自动同步。

手机曾检测到本地联通 DNS，调整后用户反馈：日本节点的 BrowserLeaks DNS 只显示日本，DNSLeakTest 显示日本与美国公共解析器；切美国节点后测试也跟随变化。这是用户提供的浏览器测试结果，未对手机完成与电脑相同的三域名 CDN 诊断。

## 设置顺序

本阶段在**电脑网络与测试网站验收完成后**开始；电脑此时仍不登录 Claude。

1. 已装 Claude 时，在系统应用信息中强行停止并确认无任务；尚未安装时先不下载 App。
2. 保存手机当前配置和界面设置，保留原订阅；保持选定节点。根据手机需求合并配置，不直接假定电脑直连策略适合手机。
3. 配置下表中的 IPv6 / DNS 项；重连 VPN 使其生效。
4. 启用系统 VPN 双开关并为 Clash 保活；已有的 Google Play 商店可先设置后台策略，未安装 Claude 的权限此时记为“待安装后设置”。
5. 在将实际使用的 Wi-Fi / 移动网络完成下方手机验收；不要开着 Claude 测试切换，也不能用电脑结果替代。
6. **手机环境通过后**，才从 Google Play 下载官方 Claude；核对发布者，设置应用权限与后台限制，保持 VPN 已连接，再首次启动并由用户登录。
7. 用户核对 Google Play 的实际商店国家、付款资料、价格和续费条款，再用有授权的付款方式订阅。只有付款方式可添加或邮箱已验证，不代表付款成功；以订单与 Claude 账号权益为准。已有订阅只核对，不重复充值。
8. 手机 Pro 权益确认后，回 [macOS 手册第 7 节](macos-runbook.md) 最后登录电脑同一账号。Agent 不代填身份材料、代付费或替用户接受付款承诺。

## Clash Meta

| 位置 / 设置 | 目标值 |
|---|---|
| 网络：自动路由系统流量 | 开 |
| 网络：DNS 劫持 | 开 |
| 网络：允许应用绕过 | 关 |
| 网络：访问控制模式 | 允许所有应用；检查没有排除 Claude |
| 网络：允许 IPv6 | 关（按核对过的上游实现，并做版本实测） |
| 覆写 / 常规：IPv6 | 已禁用 |
| 覆写 / DNS：IPv6 | 已禁用，而不是“不修改” |
| 覆写 / DNS：追加系统 DNS | 已禁用 |
| 系统：私人 DNS | 本方案采用关闭，由 Clash 统一解析 |
| Chrome：使用安全 DNS | 本方案采用关闭，由 Clash 统一解析 |

三处 IPv6 控制不是同一个开关。核查过的 Clash Meta 上游 `TunService.kt` 在“允许 IPv6”关闭时不向 VPN 添加 IPv6 地址、路由和 DNS，也未调用 allowFamily 放行该地址族；Android 默认阻断未加入 VPN 的地址族。安装的是其他分支或版本时，应重新核对并实测，不能把开关文字当成唯一依据。

“绕过私有网络”针对局域网，不是允许所有公网流量绕过。需要打印机、NAS、投屏时保留并验收；不需要时可关闭以减少例外。VPN 已接管的流量仍可被 Clash 规则设为 DIRECT。

保持已有 Stack Mode、系统代理及嗅探选项；不要一次把所有“不修改”改成开或关。配置合并后的含义比开关数量重要。

## 小米系统设置

- 设置中搜索 **VPN**，进入 Clash Meta 对应 VPN 的设置。如果系统和应用支持，同时开启 **“始终开启的 VPN”** 和 **“屏蔽未使用 VPN 的所有连接”**。其他系统可能分别称为“始终开启 VPN”和“阻止未通过 VPN 的连接”。仅开前者不能代替后者。
- 在 **应用设置 → Claude → 省电策略** 中，建议选择 **“禁止后台运行”**；在 **应用设置 → Google Play 商店 → 省电策略** 中同样选择 **“禁止后台运行”**。不同 HyperOS 版本可能叫“限制后台活动”或“严格控制后台运行”，按本机实际选项核对并记录。目的是减少离开前台后的联网活动。
- **Clash Meta 采用相反设置**：允许后台自启动、电量策略选无限制；可配合最近任务锁定。不要对代理应用使用“禁止后台运行”，否则可能影响代理持续工作。
- Claude 可拒绝位置权限。**禁止后台运行不等于强行停止，也不保证应用退出前台后立即没有连接**；变更节点或网络前，仍在应用信息中明确强行停止 Claude，并确认其他设备 / 任务状态。Play 商店正在下载、更新或付款时，先完成操作，再退出；限制后台后需留意后台下载、更新和通知是否符合使用需求。
- 不需要的精确位置、附近设备权限可拒绝；不为此关闭 Google Play 服务、系统推送或任意修改设备标识。

“阻止未通过 VPN 的连接”会在 VPN 停止时让普通应用断网，这是预期行为；它不阻止 VPN 应用根据自己的规则进行 DIRECT 出站。启用前确认用户接受该影响。

Android 没有可通用于所有机型的“整个系统 IPv6 关闭”按钮。APN 的 IPv4 设置仅影响移动数据，而且可能影响联网；不是本指南的首选步骤。不 Root、不修改内核、不盲改 APN。

## 可选的应用联网限制与 SIM 边界

2026-11-13 用户反馈：Claude 仅允许 SIM 2 移动数据，禁用 SIM 1、WLAN 和后台联网；使用时仍先开启 Clash 与 VPN 双开关。这是用户偏好的网络入口限制，不是所有读者必选项，也不是 Agent 对手机执行后的实测。

需要 Wi-Fi 使用 Claude 的读者不应照抄关闭 WLAN；应用联网许可、Clash 接管与 VPN 断线阻断要分别验收。限制使用哪张 SIM 联网，不能据此断言应用无法读取另一张 SIM 的信息。后台联网开关也不等同于省电策略，切网前仍需强行停止。

**SIM 国家代码问题暂缓，状态为未解决。** 尚未验证 Claude 当前 Android 版本是否读取 / 上传该字段，也未找到足以确认小米 17 普通权限开关或“空白通行证”能阻断相关接口的证据。拒绝电话 / 位置权限、开 VPN、改时区和限制 SIM 联网均不作为“SIM 信息已隐藏”的验收证据。按用户决定，不为此继续 Root、装 Hook 模块、刷机或改 SIM；不阻塞其他已经授权的整理工作。

## 退出 Claude 后，恢复境内直连的顺序

目标是让 Claude 停止后，再改变手机网络。**不能仅靠“禁止后台运行”推断 Claude 已停止**；按 Home、返回、划掉最近任务和强行停止不是同一个动作。

1. 完成 Claude 当前任务，在 **系统应用信息 → Claude → 强行停止** 中明确停止应用；确认没有仍在使用 Claude 的浏览器页面或其他客户端。Google Play 商店若刚用于订阅、下载或更新，先等操作完成，需要一并停止时同样通过应用信息操作。
2. 若“始终开启的 VPN”和“屏蔽未使用 VPN 的所有连接”仍生效，仅停止 Clash 可能被自动重连，或使手机断网。**确实要恢复普通境内直连时**，在应用已停止的前提下，按本机界面关闭自动保持 VPN 的设置、解除无 VPN 连接阻断，再断开 Clash VPN。此时系统不再提供 VPN 断线保护，这是本次有意切网的边界。
3. 境内直连期间保持 Claude 停止，不重新打开应用、Claude 网页或会启动它的链接。后台省电限制只作为补充。
4. 下次使用前，先连接 Clash Meta、选定已验收配置和节点，重新开启 VPN 的两个保护开关，完成当前网络的无账号检查，再打开 Claude；不要先启动 Claude 再连 VPN。

Agent 不得因为用户表达这一目标，就在 Claude 使用期间替用户执行断开 VPN。换网步骤需要用户完成任务后按已授权范围进行。

## 手机验收

- 在手机实际浏览器按 [多站点检测流程](network-checks.md) 使用 IPinfo.CV 与 Net.Coffee；记录网站分流中的国内 IPv4 出口，并区分预期直连与旁路。独立执行 DNS 和 WebRTC 测试，不只看综合低风险提示。
- IPv4 正常，出口符合预期；[test-ipv6.com](https://test-ipv6.com/) 等显示公网 IPv6 不可用。
- [BrowserLeaks DNS](https://browserleaks.com/dns) 与 [DNSLeakTest](https://www.dnsleaktest.com/) 检查没有未经解释的本地运营商解析器。
- 目标域名 / CDN 验收按 macOS 手册中的同一证据标准，不能用手机 DNS 国旗代替。
- 检查休眠 / 息屏后 Clash 仍工作。若测试断线阻断，先停止 Claude，再停止 VPN，以无账号普通网页确认断网，最后恢复 VPN 并重新验收。
- 分别记录 VPN 两个开关、Claude / Google Play 商店的后台策略、Clash Meta 保活策略；界面文案不同或选项不可用时注明，不能替用户假定已开启。应用后台限制不替代 VPN 断线阻断。
- 手机 DNS 测试通过，不代表所有其他 App 都使用相同解析方式；Claude 登录后还需看实际连接。
